# UC-0101. 테넌트 별 AI 자원 사용 인증키를 신청한다

## 1. Use Case 개요

| 항목 | 내용 |
|---|---|
| Use Case ID | UC-0101 |
| Use Case 명 | 테넌트 별 AI 자원 사용 인증키를 신청한다 |
| 주요 Actor | 개발자, 관리자 |
| 주요 시스템 | 개발시스템, AI Gateway |
| 목적 | 개발자가 정보시스템에서 사용할 수 있는 AI 자원(Model/RAG/MCP)를 선택하고 인증키 발급을 신청한다 |
| Trigger | 개발자가 AI 자원을 활용하는 Agent/AI 서비스를 개발하고자 하는 경우, 또는 기존 인증키에 없는 AI 자원(예: 신규 MCP)이 추가로 필요한 경우, 또는 기존 인증키가 만료를 앞둔 경우 |
| 관련 SFR | SFR-010, SFR-005, SFR-009 |

## 2. 사전 조건

- 개발자는 개발시스템에 권한이 있으며 정보시스템에 소속되어 있어야 한다.
- 개발시스템에 사용 가능한 AI 자원(Model/API/MCP)이 등록되어야 한다.
- 관리자는 테넌트별 AI 자원 사용 정책 및 권한을 사전에 설정해 두어야 한다.
- "AI Gateway에 등록 된 AI 자원은 테넌트와 상관없이 사용 가능하다." 이지만, Model의 경우는 테넌트에 따라 과금이 되기 때문에 정보시스템이 신청한 테넌트에서 제공하는 모델만 사용 가능하다. 같은 이유로 공통RAG, 공통MCP는 Provider에게 청구가 된다.
- 인증키는 신청 시점에 선택한 AI 자원 세트로 고정되며, 발급 이후 자원 추가는 지원하지 않는다. 새로운 자원이 필요한 경우 별도의 신규 신청으로 처리한다.

## 3. 기본 시나리오

| 단계 | Actor | 수행 내용 |
|---|---|---|
| 1 | 개발자 | 개발시스템에서 AI Gateway 관리 화면에서 인증키 신청한다. |
| 2 | 개발자 | 인증 키를 사용 할 정보시스템을 선택한다. |
| 3 | 개발시스템 | 해당 테넌트에 허용된 AI 자원(Model/RAG/MCP) 목록을 제공한다. |
| 4 | 개발자 | 사용 할 AI 자원(Model/RAG/MCP)을 선택하고 제출한다. |
| 5 | 개발시스템 | 정보시스템과 인증 키 신청 내역을 저장하고 관리자에게 알린다. |
| 6 | 관리자 | AI 자원 신청 현황을 조회하고 신청 내용과 권한을 확인한다. |
| 7 | 관리자 | 신청 내용을 승인한다. |
| 8 | 관리자 | 테넌트의 키를 확인하고 인증 키 발급을 진행한다. |
| 9 | AI Gateway | 유효기간(최대 1년)을 설정하여 인증 키를 발급한다. |
| 10 | 개발시스템 | 인증키와 사용 가능한 AI 자원/권한/유효기간 정보를 저장한다. |
| 11 | 개발시스템 | 개발자에게 인증키 및 사용 가이드를 알린다. |

## 4. 예외/대안 시나리오

- 해당 AI 자원 사용 권한이 없는 경우 → 사용 불가 오류 메시지
- 개발시스템/정보시스템 권한이 없는 경우 → 개발시스템에서 권한 획득 후 신청
- 관리자가 신청을 반려하는 경우 → 반려 사유와 함께 개발자에게 통보, 인증키 미발급
- 인증키가 만료된 경우 → 사용 불가 오류 메시지, 연장 불가, 신규 신청 필요
- 인증키가 폐기된 경우 → 사용 불가 오류 메시지, 재발급(신규) 신청
- 인증키 만료일이 임박한 경우 → 만료 전 개발자에게 알림 발송(연장 불가 안내 포함)

## 5. 사후 조건

- 테넌트와 인증키 간 관계가 등록된다.
- 인증키별 사용 가능한 AI 자원이 정의되며, 발급 이후 변경되지 않는다.
- 표준API 및 표준MCP 호출 시 사용되는 인증키를 통해 테넌트와 권한을 식별할 수 있다.
- 인증키는 발급일로부터 최대 1년의 유효기간을 가지며, 만료 시 자동으로 사용이 중단된다.
- 하나의 정보시스템이 여러 개의 인증키(자원 세트별로 상이)를 동시에 보유할 수 있다.

## 6. 미결/후속 검토 사항

- 만료 전 알림의 구체적 시점(예: D-30, D-7 등)은 별도 정책으로 확정 필요.
- 만료 알림 수신 대상(개발자만 / 정보시스템 관리 담당자 포함 여부) 확정 필요.
- 정보시스템 1개당 보유 가능한 인증키 개수 제한 여부는 UC-0301/UC-0302(관리 UC) 상세화 시 함께 검토.
