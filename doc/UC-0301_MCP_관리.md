# UC-0301. MCP를 관리한다

> ⚠️ 본 문서는 원본 PPTX(Slide 2)의 Use Case 목록에는 존재하나 상세 시나리오가 작성되지 않았던 항목입니다. 아래 내용은 다른 확정된 UC(주로 UC-0103)에서 논리적으로 도출 가능한 최소 범위만 채운 초안이며, 대부분의 세부 사항은 별도 확정이 필요합니다.

## 1. Use Case 개요

| 항목 | 내용 |
|---|---|
| Use Case ID | UC-0301 |
| Use Case 명 | MCP를 관리한다 |
| 주요 Actor | 관리자 |
| 주요 시스템 | AI Gateway |
| 목적 | 관리자는 MCP서버 또는 Rest API를 통해 제공 할 MCP를 등록한다 |
| Trigger | 신규 MCP(공통RAG, 외부MCP 등)를 AI Gateway를 통해 제공해야 하는 경우 |
| 관련 SFR | SFR-005, SFR-009 |

## 2. 사전 조건 (초안)

- 관리자는 MCP 등록 권한을 보유하고 있어야 한다.
- 등록 대상 MCP 서버(또는 이를 제공하는 Rest API)가 사전에 구축되어 있어야 한다.

## 3. 기본 시나리오 (초안 — 세부 단계 미확정)

| 단계 | Actor | 수행 내용 |
|---|---|---|
| 1 | 관리자 | AI Gateway 관리 화면에서 MCP 등록을 요청한다. |
| 2 | 관리자 | MCP 서버 Endpoint, 제공 Tool 목록, 접근 방식(내부/외부망) 등 등록 정보를 입력한다. |
| 3 | AI Gateway | 등록 정보의 유효성(연결 가능 여부 등)을 확인한다. *(확인 방식 미정의 — 아래 미결사항 참고)* |
| 4 | AI Gateway | MCP를 등록하고 표준 MCP Endpoint로 변환하여 제공 가능하도록 설정한다. |
| 5 | 관리자 | 등록된 MCP의 사용 가능 여부(Tenant/Agent별 허용 정책)를 설정한다. |

## 5. 사후 조건 (초안)

- 등록된 MCP는 UC-0101(인증키 신청) 시 개발자가 선택 가능한 자원 목록에 노출된다.
- 등록된 MCP는 UC-0103을 통해 Agent가 표준 MCP 방식으로 호출할 수 있다.

## 6. 미결/후속 검토 사항 (전면 재검토 필요)

- **MCP 상태 확인(Health Check) 방식 미정의**: 등록 시점 1회성 검증인지, 등록 이후 주기적 상태 점검을 수행하는지 확정 필요.
- **MCP 스펙 변경 처리 미정의**: 이미 등록된 MCP의 Tool이 추가/삭제/변경되는 경우 관리자가 어떻게 갱신하는지, 이 변경이 이미 해당 MCP를 사용 중인 인증키/Agent에 어떤 영향을 주는지 정의 필요. (UC-0101에서 "인증키 발급 후 자원 세트는 고정"으로 확정했으므로, MCP 자체 스펙이 바뀌는 경우와는 별개 이슈로 다뤄야 함.)
- **MCP 비활성화/삭제 절차 미정의**: 삭제 시 이미 사용 중인 Agent에 대한 영향(즉시 차단/유예기간 등) 미정의.
- **내부 자원(공통RAG) vs 외부 자원(외부MCP) 등록 절차 분리 여부**: Slide 1(SFR-009)에 따르면 외부MCP는 인터넷연계망 AI Gateway를 통해 별도로 등록/관리되는 구조로 보이는데, 이 UC가 두 케이스를 모두 다루는지 아니면 별도 UC로 분리해야 하는지 확정 필요.
- **등록 시 파라미터 정의 방식**: UC-0103 미결사항에서 언급된 "테넌트/Agent 구분 Parameter"를 이 UC(등록 시점)에서 정의하는지, 호출 시점(UC-0103)에서 정의하는지 확정 필요.
